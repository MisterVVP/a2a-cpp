# Task 4 — SEO and Release Hardening

## Goal

Improve discoverability, navigation quality, and release-readiness for the first public docs release.

## Scope

- Refine page titles/headings for target search intent.
- Use clear, query-friendly page names where supported by structure.
- Add internal links across critical user journeys:
  - homepage ↔ quickstart ↔ client sending ↔ server executor ↔ transports ↔ auth
- Ensure the homepage clearly states SDK scope and capabilities.
- Keep root `README.md` concise with strong link-out to documentation website.
- Keep `api-reference.md` as a clear placeholder until generated API docs (e.g., Doxygen) are added.

## Deliverables

- Improved docs information scent for users and search engines.
- Coherent cross-linking across top-value pages.

## Acceptance Criteria

- Core launch pages are complete and cross-linked:
  - `/`
  - `getting-started/quickstart.html`
  - `client/sending-messages.html`
  - `server/custom-executor.html`
  - `transports/rest.html`
  - `transports/json-rpc.html`
  - `auth/overview.html`
  - `build/cmake.html`
- Terminology consistently reflects the SDK’s value proposition.

## Out of Scope

- Full autogenerated API reference publication.
